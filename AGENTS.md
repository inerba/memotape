# Sbobino

App desktop Tauri 2 + React, solo Windows x64, che trascrive in locale audio, video e Registrazioni.

- Requisiti di prodotto: `PRODUCT.md`, la fonte di verità. Aggiornalo quando cambia un requisito.
- Glossario: `CONTEXT.md`. Usa i suoi termini nel codice, nei test e nei commit (Sorgente, Attività, Frase, Parziale…).
- Decisioni: `docs/adr/`. Ricerche con fonti e versioni verificate: `docs/research/`.
- Spec e ticket: `.scratch/sbobino/`.

## Comandi

| Comando | Cosa fa |
|---|---|
| `bun install` | dipendenze e hook git (Husky) |
| `bun tauri dev` | avvia l'app; in debug rigenera `src/bindings.ts` |
| `bun run typecheck` | `tsc --noEmit` |
| `bun run test` | test del frontend (`bun test src`, file `*.test.ts` accanto al codice) |
| `bun run check` / `bun run fix` | Biome via ultracite, controllo / correzione |
| `bun run format:backend` | `cargo fmt --check` (per correggere: `cargo fmt` in `src-tauri`) |
| `bun run lint:backend` | `cargo clippy --all-targets -- -D warnings` |
| `cargo test` (in `src-tauri`) | test Rust |
| `bun tauri build` | installer NSIS in `src-tauri/target/release/bundle/nsis/` (vedi "Installer") |

Ogni ticket si chiude con i sei controlli verdi (da `typecheck` a `cargo test`; `bun tauri build` non è un controllo). Lancia una sola build Rust alla volta: condividono `src-tauri/target`.
Il pre-commit esegue `bunx ultracite fix` sui file staged (lint-staged).
Commit con prefissi convenzionali (`feat:`, `fix:`, `docs:`, `chore:`, `test:`, `refactor:`).

## Prerequisiti di build

- Rust stable MSVC (`x86_64-pc-windows-msvc`, almeno 1.90 per `tauri` 2.12) e Visual Studio 2022 con il workload C++.
- Bun 1.4 e Node 22.22 o successivo (lo richiede `lint-staged` 17).
- Da M1 in poi, per la pipeline audio:
  - CMake nel PATH: lo usano `opus` e `transcribe-cpp`;
  - Vulkan SDK LunarG (`VULKAN_SDK` impostata), per la feature `vulkan` di `transcribe-cpp`;
  - lo zip ufficiale `onnxruntime-win-x64-1.24.2.zip` dalle [release GitHub di Microsoft](https://github.com/microsoft/onnxruntime/releases/download/v1.24.2/onnxruntime-win-x64-1.24.2.zip) (74 075 355 byte, SHA-256 `8e3e9c826375352e29cb2614fe44f3d7a4b0ff7b8028ad7a456af9d949a7e8b0`), estratto **fuori dal repo**. Sulla macchina di sviluppo sta in `..\sbobino-deps\onnxruntime-win-x64-1.24.2`, accanto alla cartella del repo;
  - il redistribuibile VC++ di Visual Studio (`VC\Redist\MSVC`, arriva con il workload C++): `build.rs` lo trova con `vswhere`, o da `VCToolsRedistDir` se impostata (prompt dei comandi di VS), e ne mette le DLL accanto all'exe;
  - un `.cargo/config.toml` locale **alla root del repo** (ignorato da git). Va alla root e non in `src-tauri`, perché Cargo cerca la config partendo dalla cwd e gli script `bun run *:backend` girano dalla root con `--manifest-path`:

    ```toml
    [env]
    LOCALAPPDATA = { value = "src-tauri/target", relative = true, force = true }
    VULKAN_SDK = { value = 'C:\VulkanSDK\<versione>', force = false }
    ORT_LIB_LOCATION = 'D:\percorso\onnxruntime-win-x64-1.24.2\lib'
    ORT_PREFER_DYNAMIC_LINK = "1"
    ```

    `LOCALAPPDATA` serve a `transcribe-cpp-sys`, che compila passando da una junction corta in `%LOCALAPPDATA%\tcs` (vedi Insidie). `relative = true` risolve il percorso rispetto alla cartella che contiene `.cargo`.
- Per trascrivere serve il modello scelto (Nemotron di default) scaricato da Impostazioni → Trascrizione in `%APPDATA%\it.sbobino.desktop\models` (`app_data_dir/models`). Senza il file Trascrivi mostra l'errore "modello assente" con il nome del modello e il link a Impostazioni.
  - Lo smoke test con i modelli veri si lancia a mano: `cargo test -- --ignored --test-threads=1` in `src-tauri`. Va lanciato in sequenza, perché due modelli caricati insieme su Vulkan da thread diversi fanno cadere il processo (`vkCreateFence: Invalid device`, poi `STATUS_STACK_BUFFER_OVERRUN`). Era già così prima del ticket v2/10. Richiede tutti e tre i modelli e con ciascuno trascrive `parlato-it.wav` (Lingua del parlato `it`) e `parlato-it.mp4` (Automatica). Lo smoke test della Diarizzazione richiede anche Sortformer: trascrive `parlato-due-voci.wav` con Nemotron e deve trovare 2 Parlanti alternati.

- La pipeline (`engine::pipeline::transcribe`) legge una fonte di frame: un iteratore di `Feed` (`Frame` da 30 ms mono a 16 kHz, `ClosePhrase`, `Progress` da inoltrare) che finisce con l'audio. La pipeline è a trazione: il motore legge i frame della Frase da un iteratore, e ogni `next()` legge dalla fonte e passa per VAD e segmentatore solo quanto serve. Così il motore in streaming riceve l'audio mentre la Frase è ancora in corso. La usa la Trascrizione dal vivo.
  - I file passano da `transcribe_file`, che non usa la trazione (ADR-0007, misure in `docs/research/trascrizione-file-veloce.md`). In un thread di `std::thread::scope`, `cut_phrases` legge la fonte `FileFrames` (decodifica e ricampiona un blocco alla volta), passa per VAD e segmentatore e manda le Frasi intere su un `sync_channel` di `PHRASES_AHEAD` (4). Intanto `transcribe_phrases` le dà al motore senza callback dei Parziali.
    - `Decoder::next_block` dà blocchi interleaved (`Block`, con `mono()` per la Trascrizione). Se c'è, `transcribe_file` passa a `FileFrames` un `ogg_opus::OggCopy`, che riceve ogni blocco (canali scesi o duplicati con `mixer::downmix`, `Resampler` alla frequenza della Registrazione, `OggOpusWriter`) e si chiude a fine file, prima della fine della Trascrizione: è il `mix.ogg` del Bino di un file.
    - Il canale tiene solo Frasi. Il progresso sta fuori, in `Shared` (`AtomicU8`): il motore lo legge dopo ogni Frase e, durante un silenzio lungo, ogni `PROGRESS_POLL` (`recv_timeout`).
    - Annulla e un errore fermano il motore. Finito il motore, `Shared::stopped` ferma il thread al frame successivo.
    - Decodifica e VAD (circa 6 s su 10 minuti) non si sommano più al tempo del motore. Per questo `VoiceDetector` è `Send`.
  - Tempi: il segmentatore conta i frame ricevuti e `PhraseStart` porta l'indice del primo frame della Frase; la pipeline conta i frame letti dal motore. Frasi e Parziali hanno `inizio_ms` e `fine_ms` (esclusa) sulla linea del tempo della Sorgente, in multipli di 30 ms; per un Parziale `fine_ms` è l'audio letto finora. Sono l'audio dato al motore, quindi comprendono prefill (300 ms) e hangover (fino a 700 ms): il silenzio tra due Frasi risulta circa 1 s più corto di quello reale, da tenere presente per le pause lunghe del Markdown e per l'attribuzione dei Parlanti.
  - `ClosePhrase` chiude la Frase in corso come a fine parlato (la Pausa dal vivo): il parlato successivo riparte dall'onset, anche se la chiusura arriva fuori da una Frase, senza il prefill dei frame già nella Frase chiusa.
- `TranscriptionEngine::transcribe` riceve i frame della Frase, la Lingua del parlato (codice dell'app o `None`) e la callback dei Parziali, facoltativa, e restituisce il testo o un `EngineError` (`Busy`, `Cancelled`, `Internal`). Con la callback (dal vivo) `TranscribeCpp` sceglie da `capabilities().supports_streaming`: per Nemotron apre uno stream per Frase (`feed` a ogni frame, Parziale = `text().display()` quando cambia, testo = `text().full` dopo `finalize`); per Whisper e Parakeet raccoglie la Frase e chiama `run`, senza Parziali. Senza callback (i file) raccoglie la Frase e chiama `run` anche con Nemotron: 2,4 volte più veloce dello stream. `TranscribeCpp::load` riscalda il modello con un `run` su 1 s di silenzio (log `modello riscaldato in …`), quindi la prima Frase non paga il riscaldamento di Vulkan. Vale per ogni caricamento: `preload`, un `take` a freddo e l'istanza in più degli Ingressi separati (`load_instance`), che costa così circa 1 s in più all'avvio della Registrazione. `Busy` (un altro stream tiene il lease del modello) diventa `modelInUse`, che non scarta il motore; con una sola Attività alla volta non capita (ADR-0003).

- `audio_toolkit` ed `engine` non dipendono da Tauri: si testano senza `AppHandle`. Le uniche seam finte nei test sono `TranscriptionEngine` e `VoiceDetector`, più il motore generico di `LoadedModel` (vedi sotto).
- Il frontend chiama il backend solo tramite `commands` ed `events` di `@/bindings`, più il protocollo `bino` del player (`convertFileSrc(path, "bino")`, vedi Player). Anche i plugin passano da un comando Rust: `open_source` usa `tauri-plugin-opener` lato Rust, quindi non servono il pacchetto npm né permessi nella capability. L'unica eccezione è la finestra: `WindowControls` (`components/window-controls.tsx`) usa `getCurrentWindow()` di `@tauri-apps/api/window` (Riduci a icona, Ingrandisci/Ripristina, Chiudi) e le barre in alto hanno `data-tauri-drag-region`; i permessi `core:window:allow-*` sono nella capability. Lo stesso vale per il drop dei file (ADR-0011): `home.tsx` ascolta `getCurrentWebview().onDragDropEvent` di `@tauri-apps/api/webview` (`dragDropEnabled: true` in `tauri.conf.json`). I percorsi arrivano con `enter` e `drop`; `dropVerdict` (`features/source/drop.ts`, puro) dice se si aprono e `DropVeil` lo mostra su tutta la finestra. Un rilascio accettato chiude Impostazioni e passa da `openPath` come Apri file, o da `browse` durante un'Attività (solo un Bino, in consultazione). `SOURCE_EXTENSIONS` in `drop.ts` è lo specchio di quello di `commands/mod.rs`: lo controlla un test Rust.
- La pipeline comunica con un solo sink di `PipelineEvent` (progresso, Parziali e Frasi). Il manager li traduce in `transcription-progress`, `transcript-partial` e `transcript-phrase`; l'esito (`TranscriptionOutcome`: `saved` con il `path` del Bino, oppure `noSpeech`) o l'`AppError` tornano come risultato del comando `transcribe`.
- Trascrizione di un file (ADR-0009): `transcribe(source, raccolta)`. Il bersaglio dell'Attività è la cartella della Raccolta (o il Bino, per Trascrivi su un Bino). `file_to_tape` (senza Tauri, testato con il motore finto) crea l'Ogg temporaneo `<nome del file>.ogg` in `.sbobino` (`recording::temp_folder`, `create_numbered`), passa l'`OggCopy` alla Trascrizione e, se il documento ha Frasi, scrive `<nome del file>.bino` nella Raccolta (o nella radice, se sparita) con `numbered` (" 2", " 3"…), `creato` = data di modifica del file (`modified_at`; se non si legge, l'inizio della Trascrizione) e `origine` = nome del file. `Temporary` cancella l'Ogg al drop, e con lui `.sbobino` se resta vuota: annullata, guasta o senza Frasi non resta nulla. Il mix ha la durata dell'originale entro 0,1 ms (test su `parlato-it.wav` e `.mp4`). Il frontend riapre il Bino del risultato con `open_bino`, così Frasi e id sono quelli del file.
- Una sola Attività alla volta: `managers::activity::Activity` (in `tauri::State`) dà un guard con `begin(stop)`, e chi arriva secondo riceve `activityInProgress`. `stop` è la closure che ferma l'Attività, chiamata da `Activity::cancel`: così `activity` non dipende da transcribe-cpp. La Trascrizione passa una closure che preme il `CancelToken` di transcribe-cpp, installato sulla sessione e passato alla pipeline: `cancel_transcription` lo preme, il motore interrompe la Frase in corso (Nemotron ha `Feature::Cancellation`) e la pipeline esce con `AppError::Cancelled` al blocco successivo, senza emettere la fine né scrivere il Bino. Il frontend mostra `cancelled` come esito, non come errore. La Registrazione passa una closure che equivale a Stop e preme anche il `CancelToken` della Trascrizione dal vivo: dopo Stop, `cancel_transcription` annulla il completamento della trascrizione.
- Registrazione (`managers::recording`): registra dagli ingressi della sorgente di registrazione delle impostazioni (`mic`, `system` o `both`: microfono, audio di sistema, entrambi mixati). Il comando `record(prefix)` è l'Attività e dura fino alla fine, come `transcribe`; il risultato `RecordingSaved { path, error, transcription }` porta il Bino, che il frontend rende la Sorgente, `error` (`deviceDisconnected` con il nome) se si è fermata da sola o il Bino non si è scritto, e l'esito della Trascrizione dal vivo (`null` se spenta). `pause_recording(paused)` e `stop_recording` agiscono su flag atomici in `Recorder` (`tauri::State`). In un solo thread bloccante: una `audio_toolkit::capture::Capture` per ingresso (cpal; `Kind::System` è il loopback) → `audio_toolkit::mixer::Mixer` → `audio_toolkit::ogg_opus::OggOpusWriter`, scritto mentre si registra.
  - La callback cpal non alloca: prende un `Vec` dal pool della sua cattura (`sync_channel` pre-riempito), copia i campioni convertiti in f32 e lo manda al worker con l'indice dell'ingresso e il timestamp `capture` in ns, su un canale comune a tutte le catture (`capture::channel`). Senza buffer libero il blocco si perde, e il mixer ne fa un buco di silenzio.
  - `Mixer` lavora sulla linea del tempo della sessione, tutta in QPC: l'origine è `Capture::now()` (`Stream::now`, lo stesso orologio dei timestamp) appena aperte le catture, e la posizione di un blocco è timestamp − origine − pause. Il worker chiama `advance(now, paused)` a ogni giro (almeno ogni 100 ms) e poi `push` dei blocchi.
    - Ogni ingresso resta entro 20 ms dai suoi timestamp: un vuoto più lungo diventa silenzio, un anticipo più lungo (blocchi sovrapposti a quanto già scritto, o catturati prima dell'origine) si scarta. Così si corregge anche la deriva rispetto a QPC, a scatti da 20 ms.
    - `advance` riempie di silenzio l'ingresso rimasto indietro di oltre 500 ms (`LAG_NS`): è il loopback a riproduzione ferma. Con solo l'Audio di sistema, nel silenzio il timer resta indietro di 0,5 s e poi recupera.
    - La pausa si misura con `now` tra l'`advance` che la vede iniziare e quello che la vede finire; i blocchi arrivati in pausa si scartano. Un salto di `now` oltre 10 s (PC sospeso) vale come una pausa.
    - Il timer (`elapsed_ms`) è la fine dell'ingresso più avanti sulla linea del tempo. `finish(stop)` completa tutti gli ingressi fino all'istante di Stop, quindi file e timer coincidono.
    - Con `with_tracks` (Ingressi separati) dà anche l'audio di ogni ingresso in `tracks()`, ricampionato nei canali e alla frequenza della Registrazione ed emesso insieme al mix: stesso tratto della linea del tempo, silenzio nei buchi, pause escluse. Il mix è la somma degli ingressi (prima del clamp). Chi lo usa svuota i buffer.
    - Canali: il mono si duplica in stereo; il loopback a più canali si scende in stereo con centrale e surround a −3 dB (ordine WASAPI assunto), in mono si fa la media di sinistra e destra. Poi ogni ingresso si ricampiona con il suo `resample::Resampler` (generico per frequenza e canali; `FrameResampler` della Trascrizione ci si appoggia) e si somma con clamp a [−1, 1].
    - Guadagno: prima del ricampionamento ogni ingresso moltiplica i campioni per il suo (`Mixer::set_guadagno`, lineare; `settings::guadagno_factor` lo ricava dai dB). Prima del primo blocco vale subito, poi ci arriva con una rampa di `GUADAGNO_RAMP_NS` (20 ms). Vale per mix e `tracks`, quindi anche per la Trascrizione dal vivo. Il picco di `take_peaks` è quello dei campioni del dispositivo per il Guadagno a fine blocco.
    - A fine Registrazione il log dice per ingresso i ms ricevuti contro i ms di timestamp (la deriva, se la consegna è continua) e i ms di silenzio inseriti e scartati.
  - `OggOpusWriter`: encoder alla frequenza delle impostazioni (`Application::Audio`), frame da 20 ms, pre-skip = lookahead × 48000 / Fs, granule = pacchetti × 960, una pagina chiusa ogni 50 pacchetti (1 s), ultimo pacchetto con `EndStream` e granule = pre-skip + durata esatta a 48 kHz (end trimming). L'`OpusHead` porta come input rate la frequenza delle impostazioni (quella dell'encoder), non quella del dispositivo. I test rileggono il file con `audio_toolkit::decode` e ritrovano la durata al millisecondo per ogni frequenza e numero di canali, anche passando dal mixer.
  - `recording-tick { elapsedMs, levels }` ogni 100 ms: `levels` è `{ microphone, system }`, il picco (0–1) di ogni ingresso registrato e `null` per l'altro. Il frontend mostra un indicatore per ingresso (`meters`) in dBFS da −60 a 0 (`levelPercent`); prima del primo tick li prende dalla sorgente di registrazione (`silentLevels`). Accanto a ogni indicatore `GuadagnoSelect` (`features/settings/guadagno-select.tsx`, la stessa tendina di Impostazioni) salva `guadagno_microfono` o `guadagno_sistema` (dB da −12 a +24 a passi di 3, `GUADAGNI`/`valid_guadagno`) con `set_settings`, che lo passa alla Registrazione in corso (`Recorder::set_guadagni`, atomici letti dal worker a ogni giro); `record` inizializza i controlli sotto lo stesso lock, così un salvataggio a cavallo dell'avvio non si perde.
  - Il nome è `recording_path` (funzione pura, per l'Ogg e per il Bino); il prefisso tradotto arriva dal frontend (`recording.prefix`), e il comando rifiuta i caratteri non ammessi nei nomi di file. L'Ogg si crea con `create_new` in `<Cartella della Libreria>\.sbobino` (attributo nascosto con `SetFileAttributesW`), dopo l'apertura dei dispositivi: un dispositivo assente (`microphoneMissing`, `outputDeviceMissing`) non lascia file vuoti.
  - A Stop, finita la coda della Trascrizione dal vivo, `record` compone il Bino (`<prefisso> <data ora>.bino` nella Raccolta passata a `record`, o nella radice della Libreria con `null`/`""` o se la sua cartella nel frattempo è sparita, con `creato` = l'ora di inizio) con le Frasi arrivate, anche se annullata o guasta, e `completa` vero solo se la Trascrizione è arrivata alla fine; senza Trascrizione dal vivo `modello` è `null` e non ci sono Frasi. Poi cancella l'Ogg e la cartella `.sbobino` se resta vuota; gli Ogg di una Registrazione interrotta da un crash restano lì. Se il Bino non si scrive, l'Ogg passa nella radice della Libreria come `<prefisso> <data ora>.ogg` (`keep_ogg`) ed è il `path` del risultato, con l'errore e il Markdown accanto: è l'unico caso in cui si salva un Markdown da solo. La regola di `completa` è la funzione pura `completa`.
  - Gli errori della callback fermano la Registrazione come Stop, tranne `Xrun`, `RealtimeDenied` e `DeviceChanged`. Su WASAPI uno stream sul dispositivo predefinito non segue il cambio di predefinito: arriva `StreamInvalidated` (o `DeviceNotAvailable` se non resta nessun microfono), e anche questo salva e mostra `deviceDisconnected` ("non è più disponibile, scollegato o cambiato in Windows"). Vale per entrambi gli ingressi, con il nome del dispositivo che si è fermato. Un errore di scrittura (disco pieno) ferma allo stesso modo con `unwritableFolder` nel risultato.
- Modelli (`managers::models`): `models.json`, accanto al modulo e incluso con `include_str!`, è l'unica fonte di URL, SHA-256, dimensione, tipo, modalità, licenza e modello predefinito; il nome del file è l'ultimo segmento dell'URL. Il core (`download`, `disk_state`, `delete`) non usa `AppHandle` e si testa contro un server HTTP sulla loopback. Il manager `Models` tiene per modello il download in corso o l'errore dell'ultimo, e li traduce in `model-download-progress` e `model-state-changed`. `download_model` torna subito: l'esito arriva con gli eventi e resta in `list_models`, e Impostazioni rilegge `list_models` a ogni `model-state-changed`.
  - `tipo` è `trascrizione` (predefinito) o `diarizzazione`: Sortformer, l'unico del secondo tipo (`models::diarizer`), non ha `modalita` e non si sceglie (le impostazioni accettano solo `find_transcriber`). Impostazioni → Trascrizione lo mostra in una lista a parte, senza la scelta. Una Trascrizione con Riconosci i parlanti lo prenota all'inizio con `Models::reserve_diarizer` (`diarizerMissing` se non è scaricato): il `DiarizerLease` lo tiene in uso (Elimina disabilitato, `delete` risponde `modelInUse`) fino alla fine, e `DiarizerLease::diarize` lo carica solo per la Diarizzazione, senza tenerlo in memoria.
- Trascrizione dal vivo (impostazione `trascrizione_dal_vivo`, casella "Trascrivi dal vivo" accanto a Registra): `record` apre il canale `engine::live::channel` e lancia `transcription::transcribe_live` in un thread bloccante, che prende il modello scelto e fa girare la pipeline sulla fonte `LiveFrames`.
  - Il thread della Registrazione passa a `LiveFeed::push` l'uscita del mixer già scritta nell'Ogg (con lo stato della Pausa), che la scende in mono, la ricampiona a 16 kHz con `FrameResampler` e manda i frame su un `mpsc` senza limite: la Registrazione non aspetta mai il motore. I tempi delle Frasi sono quindi quelli dell'audio salvato, pause escluse. All'inizio di una pausa `Mixer::advance` completa di silenzio gli ingressi rimasti indietro (il loopback fermo tratterrebbe fino a `LAG_NS`) ed emette tutto l'audio prima della pausa, e `LiveFeed` manda `ClosePhrase` dopo di esso.
  - A Stop `LiveFeed::finish` manda l'ultimo frame e chiude il canale, e `record` emette subito un `transcription-progress` indeterminato, che porta il frontend nella fase `completing` ("Completamento della trascrizione…", con Annulla) anche se il motore è a metà Frase. Poi `LiveFrames` emette `Progress` (frame letti dalla pipeline / frame mandati) a ogni cambio: con Whisper e Parakeet arriva a 100 quando l'ultima Frase è letta, prima che il motore la trascriva. `record` aspetta la fine della pipeline: l'Attività finisce a coda vuota. Poi `record` compone il Bino e `transcription::finish_live` dà al documento il suo nome e dice com'è finita (`LiveTranscription`: `saved`, `noSpeech`, oppure `failed` con `cancelled` o l'errore); salva il Markdown solo se `recording` non è un Bino (`keep_ogg`). Se la Registrazione non parte (`microphoneMissing`…) `record` annulla la pipeline e risponde subito, senza aspettare il caricamento del modello.
  - Se il modello non si carica la pipeline esce con `liveTranscriptionUnavailable` (nome del modello) ed emette `live-transcription-failed`, come per un guasto: la Registrazione continua, il frontend mostra l'avviso con il link alle Impostazioni (`needsSettings`) e `LiveFeed` scarta i frame.
  - Ingressi separati (`Settings::ingressi_separati`: dal vivo, `modalita_dal_vivo` = `ingressiSeparati` e sorgente Entrambi): il mixer gira con `with_tracks` e `run` scrive tre Ogg temporanei (`<nome>.ogg` del mix, `<nome>.microfono.ogg`, `<nome>.sistema.ogg`); i due Ingressi, non il mix, vanno ciascuno al suo `LiveFeed`. `live::channels(rate, canali, n)` crea i canali con un progresso dello smaltimento comune (frame consumati da tutte le pipeline / mandati). `transcribe_live` riceve le fonti con il loro `Ingresso`, prende in prestito il motore tenuto e carica con `Models::load_instance(&lease)` un'istanza in più per ogni fonte oltre la prima (transcribe-cpp ammette un solo stream per modello), poi fa girare una pipeline per fonte in thread con `std::thread::scope`, ognuna con il suo Silero; l'istanza in più si libera alla fine, il prestito tiene il modello `inUse`. Le Frasi entrano in `Transcript` e in `LastTranscript` in ordine di inizio (`Transcript::insert`). Un guasto di una pipeline emette subito `live-transcription-failed` e l'altra continua; l'esito è il primo errore. Il Bino ha anche `microfono.ogg` e `sistema.ogg` e `modalita: ingressi_separati`; se non si scrive, gli Ogg degli Ingressi restano nella cartella nascosta.

- Markdown e Copia testo (`transcript`, senza Tauri; i comandi `bino_text` ed `export_markdown` per un Bino, `transcript_text` per la Trascrizione in corso o annullata): `Transcript` ha titolo (nome della Sorgente senza estensione), data e ora locali di inizio, durata, nome del modello, Lingua del parlato e le Frasi con i tempi; `render` lo scrive in Markdown o in testo semplice (`CopiaCome`). Le Frasi hanno `ingresso` (`transcript::Ingresso`: `mix`, `microfono`, `sistema`, il nome viene dalle chiavi `settings.recording.inputs.*`) e `parlante` (il numero, da 1; l'etichetta è `transcript.speaker`, "Parlante {{n}}"): se almeno una ha un'etichetta (il mix non ne ha) si va a capo a ogni cambio di etichetta (`**Microfono · Parlante 2:**`), altrimenti dopo oltre 2 s di silenzio. Il silenzio si stima come buco tra le Frasi + hangover + prefill (vedi "Tempi" sopra), ma solo se il buco non è zero: le Frasi spezzate a 18 s nel parlato continuo restano nello stesso paragrafo. Dopo una Frase chiusa senza hangover (taglio a 18 s seguito da silenzio, Pausa) la stima eccede di 0,7 s. In Markdown un paragrafo che comincerebbe un elenco o un titolo (`- `, `1. `, `#`) si scrive con un backslash.

- Bino (`tape`, senza Tauri; ADR-0005): zip (crate `zip`) con `mix.ogg` non compresso e `trascrizione.json` (schema v1 della spec, `tape::Document`) compresso con deflate. `write` crea il file con `create_new` e lo cancella se non riesce a finirlo; `read` legge prima solo `version` (oltre `VERSION` dà `unsupportedBino`, anche se il resto dello schema è cambiato) e ignora i campi sconosciuti; `rewrite` scrive `<nome>.bino.tmp` copiando le altre voci con `raw_copy_file` e lo rinomina sopra il Bino. `origine` (il file da cui viene un Bino trascritto) è facoltativo e non si scrive se manca: `version` resta 1.
  - Forma d'onda (ADR-0010): la voce facoltativa `forma-onda.json` (deflate), un array di al più `forma_onda::VALORI` (1000) picchi 0–1 del mix. La calcola `forma_onda::Picchi` (picchi ogni 20 ms, poi `regroup`), che sta dentro `OggOpusWriter`: `write` riceve quella del mix dalla Registrazione (`Recorded::forma_onda`) e da `file_to_tape` (`OggCopy::forma_onda`, un `OnceLock` riempito da `finish`), senza decodificare. È una voce e non un campo del documento perché `rewrite` copia le altre voci: correzioni, rinomine e Trascrivi su un Bino la conservano. `tape::forma_onda` la legge (`None` se manca, è illeggibile o è vuota); `save_forma_onda` la aggiunge a un Bino che non la ha, sotto il lock di `update`.
  - Data (`tape::set_creato`, comando `set_creato(path, local)`): riceve data e ora locali senza fuso (`2026-10-03T17:05`, il valore del campo `datetime-local`), le rende `creato` con lo scarto da UTC in vigore in quel giorno (un'ora che non esiste per l'ora legale si rifiuta) e riscrive il Bino con `tape::update`; il comando passa da `write_tape` come la correzione e restituisce il `creato` scritto. Il nome del file non cambia.

Misurato su un Bino di un'ora (14 MB di mix, 600 Frasi): 45 ms in release, 130 in debug, quindi niente salvataggio in background. Il comando (`write_tape`, come `rename_parlante`) prende `Activity::write` solo per la scrittura e poi riallinea l'indice, così la correzione si trova subito. Correzioni e rinomine passano da `tape::update`, che le serializza con un lock di processo: durante un'Attività `Activity::write` non blocca le scritture su un altro Bino, e due scritture dello stesso Bino perderebbero una modifica e condividerebbero il `.tmp`. Senza Attività una seconda scrittura dello stesso Bino mentre la prima è in corso riceve `activityInProgress`: il testo resta scritto e si riprova.

Una colonna FTS5 non può chiamarsi come la tabella (`vtable constructor failed`). `Library::search(query, raccolta)` (comando `library_search`, `raccolta` come altrove: `null` tutta la Libreria, `""` Senza raccolta) mette ogni parola tra virgolette come prefisso (`"parola"*`, così i caratteri speciali di FTS5 non contano; le parole senza lettere né cifre si scartano), tutte nella stessa riga. I Bini si ordinano per la somma dei `bm25` delle loro righe (chi parla di più dell'argomento viene prima), con al più `FRASI_PER_TAPE` (5) Frasi per Bino, per pertinenza, mostrate per inizio, e `TAPES_PER_RICERCA` (50) Bini. L'estratto è `snippet()` del testo con le parole tra `\u{1}` e `\u{2}` (`MARK_START`/`MARK_END`, `markedParts` in TS), con il nome del Parlante davanti se le parole sono lì. Il `DELETE` su `percorso` scorre tutta la tabella FTS: si fa solo per i Bini già indicizzati.
  - Frontend della ricerca: il campo della barra laterale (Ctrl+K lo raggiunge, Esc lo svuota) cerca sempre in tutta la Libreria; con testo, `SearchResults` (`features/library/search-results.tsx`, chiamato con `raccolta={null}`, quindi senza "Cerca in tutta la Libreria") prende il posto dei Recenti, cerca 150 ms dopo l'ultimo tasto e a ogni `library-changed`, e scarta le risposte superate. Il clic su una Frase passa a `openFromLibrary` un `PhraseRef` (Ingresso e `phraseId`), che `home.tsx` tiene in `highlight`: `TranscriptView` evidenzia quella Frase e la porta in vista. La vista ha come `key` il Bino e `revision`, così il clic sul titolo del Bino già aperto riparte dall'inizio.
  - Operazioni: `create_raccolta`, `rename_raccolta` (anche solo maiuscole/minuscole), `delete_raccolta` (solo vuota, `raccoltaNotEmpty`), `rename_bino` (tiene l'estensione del file), `move_bino` (anche da fuori: Aggiungi alla Libreria; tra volumi copia e cancella), `trash_bino` (`SHFileOperationW` con `FOF_ALLOWUNDO`; un volume senza Cestino, per `SHQueryRecycleBinW`, si rifiuta, e con il Cestino disattivato è Windows a chiedere prima di cancellare per sempre). Ognuna allinea l'indice. I nomi passano da `validate_name` (`invalidName`: vuoto, `<>:"/\|?*` e controlli, `CON`/`NUL`/`COM1`…, punto o spazio in fondo, punto in testa); un nome già usato nella cartella dà `nameTaken`, un Bino sparito `binoNotFound`. `nameProblem` in `features/library/library.ts` è lo specchio in TS.
  - `managers::library`: `LibraryState` tiene la `Library` della cartella delle impostazioni e la riapre se cambia; `change` esegue un'operazione ed emette `library-changed`, a cui il frontend (`useLibrary`) rilegge `library_list`. Si allinea all'avvio, a ogni `Focused(true)` della finestra (in un thread), in `open_bino` prima di leggere, dopo `record`, `transcribe`, `rename_parlante`, `edit_frase` e `set_creato`, e quando cambia la Cartella della Libreria. Niente watcher.
  - Scritture durante un'Attività: `Activity::begin` riceve il bersaglio (il Bino di Trascrivi su un Bino, la cartella della Raccolta di `record`). `Activity::write(path)` serve ai comandi che scrivono un Bino o una Raccolta: senza Attività la prende per il tempo della scrittura, con un'Attività su altro scrive senza, e rifiuta con `activityInProgress` se il bersaglio è `path` o ci sta dentro (`library::inside`, senza distinguere maiuscole e minuscole). Così fanno anche `rename_parlante`, `edit_frase` e `set_creato`. Nel frontend `movedPath` segue la Sorgente e il Bino consultato dopo `rename_bino`, `move_bino` e `rename_raccolta`.
  - Frontend: `home.tsx` è barra laterale (`Sidebar`: marchio, Nuova registrazione ▾ (`RecordMenu`) e Importa un file, ricerca, i Recenti di tutta la Libreria per giorno con `groupByDate`, l'Attività con `activitySummary` (testo, percentuale, Registrazione) solo mentre è in corso, in fondo Libreria con il numero dei Bini e Impostazioni) e pannello centrale. Il pannello ha in alto `TopBar` (trascinabile: il percorso a sinistra, Copia testo e "…" a destra, sotto i pulsanti della finestra) e in fondo `Dock` (il player, la barra della Registrazione o `ProgressDock`, l'avanzamento con Annulla). Le viste: `AllBini` (la Libreria: le Raccolte come pillole, Nuova Raccolta, Rinomina ed Elimina di quella scelta, l'elenco con Sposta in… ed Elimina; le intestazioni Titolo, Data e Durata ordinano con `nextOrder`/`sortBini`, ricordato in `localStorage` `sbobino.order` e riletto con `orderOf`), il Bino consultato durante un'Attività (`browsed`), la Registrazione in corso (`LiveView`), il Bino Sorgente (`BinoPane`), un file (`FileView`: nome, Trascrivi ▾ e, dopo Annulla, le Frasi arrivate) e senza Sorgente `Welcome`. Finita l'Attività, torna la sua vista con il suo esito come Sorgente (il Bino di una Registrazione o di un file resta aperto). Niente status bar: `BannerView` è l'avviso sospeso sotto la barra in alto, da `shownBanner`: prima l'errore di un'operazione (`notice`), poi un messaggio (`message`, il Markdown esportato), poi `bannerOf(status)` (errori, esiti, l'errore della Trascrizione dal vivo, con il link alle Impostazioni se serve). Gli esiti e `notice`/`message` spariscono dopo 6 s, gli errori della fase restano finché non si chiudono (`dismissed`). `settings.raccolta` (`null` Tutta la Libreria, `""` Senza raccolta) passa da `chosenRaccolta`, che rende Tutta la Libreria una Raccolta sparita, e va a `record` e `transcribe`: si sceglie nella Libreria (che dice dove vanno le cose nuove) o dal percorso in alto di un Bino.
  - Vista di un Bino (`BinoPane` in `home.tsx`): `TopBar` con il percorso (Raccolta, che porta alla Libreria lì, e titolo, con il percorso del file nel tooltip), Copia testo e `BinoMenu` ("…": Esporta Markdown…, Mostra in Esplora file, `MoveSelect`, `TranscribeOptions` con Trascrivi di nuovo, Elimina); nel documento `BinoHeader` (titolo grande che un clic rinomina, giorno con `dayText`, ora e durata, che un clic cambia con `<input type="datetime-local">` e `set_creato`, etichette `Chip`), `DocumentToolbar` (schede Trascrizione e Parlanti, interruttore Segui l'audio) e `TranscriptView` o `ParlantiTab`; senza Frasi `BinoEmpty` con Trascrivi ▾. Il testo è modificabile se l'Attività in corso non lavora su quel Bino. Nessuna textarea: niente testo "modificato a mano" né conferme per aprire un Bino o registrare.
  - `TranscriptView` (`features/transcription/transcript-view.tsx`) è lo scorrimento del documento (con `header` in cima e `empty` senza turni) e mostra `turnsOf`: per turno il pallino del colore (`voiceColors`), il nome, il tempo che porta lì il player e ▶ (`playFrom`), all'estremità destra Copia turno (`CopyTurn`: compare in hover o con il focus nel turno e copia `turnText`, sempre in testo semplice), poi le Frasi in un paragrafo, i Parziali in corsivo. Il tempo delle altre Frasi compare sopra la Frase in hover o con il focus, senza spostare il testo. Una Frase modificabile è uno `span` `contentEditable="plaintext-only"` con `role="textbox"`: all'uscita (anche con Invio) confronta il testo con quello della Frase e chiama `edit_frase`; Esc rimette il testo e rimonta lo span. Lo span ha come `key` il testo e un contatore, così React non riscrive mai un nodo di testo che l'utente ha modificato; un salvataggio fallito lascia il testo scritto. `withTesto` applica la correzione alla `Conversation`.
  - Menu a comparsa (`components/popover-menu.tsx`): Popover API nativo (`popover="auto"`, `popoverTarget`) ancorato al pulsante con l'anchor positioning di CSS (`anchor-name`, `position-area`), senza dipendenze. Le classi dell'ancora sono scritte per intero in `ANCHORS`, perché Tailwind le trovi: un menu per tipo per pagina (`transcribe`, `record`, `more`), quindi `Welcome` non ripete `RecordMenu` ma un pulsante semplice. `TranscribeMenu` (modello tra quelli scaricati, Lingua del parlato, Riconosci i parlanti; il pulsante dice "Trascrivi · Italiano") e `RecordMenu` (Registra da, Trascrivi dal vivo, Riconosci i parlanti della Registrazione) salvano subito con `SettingCheckbox` e `set_settings`.
  - Player (`features/player`, ticket libreria/04): `BinoPane` tiene `usePlayer` (posizione, durata, Play/Pausa, `follow`) e lo passa a `Player`, il tag `<audio>` con `src = convertFileSrc(path, "bino")` (`http://bino.localhost/<percorso codificato>`), e a `TranscriptView`. Il protocollo (`player::respond`, in `spawn_blocking`) serve solo il mix di un `.bino`: `window` (pura) dà 200 senza `Range` o con una non capita, 206 con al più 1 MB, 416 oltre la fine; `read` apre il Bino con `tape::Mix` e lo chiude a ogni richiesta, così correzioni, rinomina e Cestino non lo trovano bloccato. La Forma d'onda viene da `bino_peaks(path, count)` (`player::forma_onda`): quella salvata nel Bino raggruppata in `count`; se manca (un Bino di prima) `decode::peaks` decodifica il mix (8 s per 25 minuti in release) e `save_forma_onda` prova una volta a salvarla, con `Activity::write`, senza errori se non riesce. È disegnata in SVG con sopra un `<input type=range>` trasparente per trascinamento, frecce e lettore di schermo. Il volume si ricorda in `localStorage` (`sbobino.volume`), la velocità no. Prima del primo ascolto nessuna Frase è evidenziata. Il player è disabilitato durante una Registrazione (`recording`) e al suo posto c'è l'avanzamento mentre Trascrivi lavora sul Bino; la vista ha come `key` il percorso, quindi aprire un altro Bino lo rimonta e lo ferma.
  - Sincronizzazione (`features/player/sync.ts`): `playingAt` dà le Frasi da evidenziare (quelle che contengono la posizione, `fineMs` esclusa; nel silenzio quella finita per ultima; la prima è quella da seguire) e `nextFollow` / `autoScroll` la macchina `following`/`free`. `TranscriptView` riconosce lo scorrimento a mano da `wheel`, dai tasti di scorrimento fuori da un campo e dal `pointerdown` sulla barra di scorrimento (non da `scroll`), sospende lo scorrimento mentre il focus è in una Frase e porta in vista (`block: "center"`) la Frase seguita solo se non si vede già. `move(ms, evento)` sposta `currentTime` senza toccare Play/Pausa e torna a `following`: la usano la barra, ±10 s, il pulsante del tempo di ogni Frase (span `data-phrase`, sempre nel layout con `opacity-0`, per non far scorrere il testo al passaggio del mouse) e il risultato di una ricerca, che prima mette in pausa. Spazio è Play/Pausa da `window` se il focus non è in un campo, un pulsante o un link; i pulsanti del player e del tempo non prendono il focus al clic (`keepFocus`).
- Modello caricato (`managers::loaded_model::LoadedModel`, dentro `Models`): il motore del modello scelto resta in memoria tra una Trascrizione e l'altra e si ricarica solo se cambia la scelta o il modello viene eliminato (`evict` prima di cancellare il file). Chi lo usa lo prende in prestito (`Models::take` / `release`); chi arriva intanto aspetta su una `Condvar`, quindi due caricamenti non si sovrappongono. `managers::transcription::preload` lo carica in background all'avvio, quando cambia il modello scelto e a fine download: serve anche a conoscere le lingue del modello. In caricamento o in uso il modello è `inUse` in `ModelInfo`: Elimina è disabilitato e il backend risponde `modelInUse`. Dopo un errore `internal` il motore si scarta e si ricarica alla Trascrizione successiva.
- Lingua del parlato: il manager la passa a `transcribe_file`, che la dà al motore a ogni Frase; `TranscribeCpp::set_cancel_token` installa solo il `CancelToken`. `engine::resolve_language` trasforma il codice nel codice offerto dal modello (`it` → `it-IT` per Nemotron), e senza corrispondenza passa `None` (automatico). Il frontend offre tutte le lingue del modello in `speechLanguageChoice`, dalle `languages` di `ModelInfo` senza regione e in ordine di nome; restano `null` finché il modello non è stato caricato una volta. I nomi vengono dalle ICU: `Intl.DisplayNames` nel frontend (`speechLanguageName`), `uloc_getDisplayLanguage` di Windows in Rust (`SpeechLanguage::name`, per l'intestazione del Markdown), con l'iniziale maiuscola.
  - Frasi inventate: su audio incomprensibile i modelli scrivono in altre lingue (misure del 2026-10-05 sui Bini dell'utente). `TranscribeCpp::transcribe` scarta il testo di una Frase con lettere di una scrittura che la Lingua del parlato non usa (`engine::foreign_script`, con `uloc_addLikelySubtags` e `uscript_getCode`/`uscript_getScript` delle ICU di Windows; il latino vale sempre), e la Frase vuota non entra nel documento. Per Whisper (`Feature::TemperatureFallback`) passa `no_speech_thold` 0 (`confident_only`): con la confidenza media sotto −1 la Frase si scarta invece di ritentare a temperatura più alta, perché se nessun tentativo passa transcribe-cpp tiene l'ultimo, a temperatura 1. Parakeet TDT v3 non ha un ingresso per la lingua (transcribe-cpp la ignora, `resolve_prompt_id` vale solo per i modelli con prompt come Nemotron) e non dice quale ha riconosciuto: `accettaLingua: false` in `models.json` (`ModelInfo::accepts_language`) fa dire al menu di Trascrivi che la scelta serve solo al filtro della scrittura. In inglese su audio italiano Parakeet può ancora sbagliare: il filtro non lo vede.
- Parziali: `transcript-partial` e `transcript-phrase` condividono `phraseId` e portano `inizioMs`/`fineMs` e `ingresso`; con gli Ingressi separati ogni Ingresso ha i suoi id da 0. Il frontend tiene una `Conversation` (`features/transcription/phrases.ts`): le Frasi in ordine di inizio (`withPhrase`) e un Parziale per Ingresso (`withPartial`); la Frase con lo stesso Ingresso e id sostituisce il Parziale. `turnsOf` la divide in turni con i Parziali al loro posto e, con gli Ingressi separati, l'etichetta a ogni cambio di Ingresso. Durante Trascrivi (fase `transcribing`) la vista non mostra il testo e Copia testo è disabilitato: le Frasi entrano nella `Conversation` ma si vedono solo alla fine, dal Bino riaperto, o dopo Annulla su un file. Una Frase finita vuota manda un Parziale vuoto e il suo id passa alla successiva. A fine Trascrizione (anche annullata) il Parziale sparisce, e quelli arrivati dopo la risposta di `transcribe` si ignorano: Tauri non ordina gli eventi rispetto alla risposta di un comando.
- Impostazioni è la route figlia `/settings` della finestra principale e la copre con un livello `fixed`: la finestra resta montata (con `inert`), così testo, eventi e una Trascrizione in corso non si perdono. Mostra una sezione alla volta (menu a sinistra, la sezione in un foglio a destra), scelta da `?sezione=` (`registrazione`, `trascrizione`, `generale`, `assistenti`, `informazioni`; senza, la prima): il link alle Impostazioni dell'avviso apre `trascrizione`.
- La logica pura del frontend vive nelle feature, con un `*.test.ts` accanto. Niente test sui componenti.
- Errori applicativi: un unico enum serializzato con un codice; il frontend mappa ogni codice a un messaggio tradotto.

## Installer

- `bun tauri build` compila frontend ed exe in release e produce solo l'installer NSIS (`bundle.targets: ["nsis"]`): `src-tauri/target/release/bundle/nsis/Sbobino_<versione>_x64-setup.exe`, circa 15 MB (90 MB una volta installato, di cui 44 di `ggml-vulkan.dll`). La prima volta la CLI di Tauri scarica NSIS e `nsis_tauri_utils`; la prima release compila transcribe-cpp da capo (circa 6 minuti). È una build Rust come le altre: niente `tauri dev` attivo intanto.
- Installa per l'utente corrente (`installMode` predefinito `currentUser`) in `%LOCALAPPDATA%\Sbobino`, senza UAC: `sbobino.exe` con accanto le DLL di `runtime-libs/`, `resources\silero_vad.onnx` e `licenses\*.txt`. L'elenco dei file è in `src-tauri/target/release/nsis/x64/installer.nsi`; `7z l` sull'installer mostra cosa contiene davvero.
- **Editore**: `bundle.publisher` è il segnaposto "EDITORE DA DEFINIRE" (si vede in App installate ed è nella chiave `HKCU\Software\<editore>\Sbobino`). Va deciso prima della prima release pubblica: cambiarlo dopo lascia la chiave del vecchio editore sui PC già installati. L'installer non è firmato (fuori perimetro).
- WebView2: l'installer usa il bootstrapper predefinito, quindi su un Windows 10 che non ce l'ha la scarica durante l'installazione (serve la rete). Windows 11 ce l'ha già.
- La disinstallazione toglie i file installati e lascia impostazioni e modelli (`%APPDATA%\it.sbobino.desktop`) e i dati della WebView, a meno di spuntare "Delete the application data" nel dialog; con `/S` non si cancellano.

### Verifica dell'installer

Sulla macchina di sviluppo, senza toccare l'app di sviluppo:

1. Installa in silenzio in una cartella di prova (per esempio nella scratchpad): `Start-Process <setup.exe> -ArgumentList "/S","/D=<cartella>" -Wait`. `/D=` va per ultimo e senza virgolette. Prima di installare e disinstallare l'installer chiude un `sbobino.exe` in esecuzione solo se è quello di `<cartella>`, non quello di `target\debug`.
2. Avvia `<cartella>\sbobino.exe` da PowerShell dopo aver tolto `ORT_LIB_LOCATION`, `VULKAN_SDK` e `ORT_PREFER_DYNAMIC_LINK` e aver ripulito il `PATH` dal Vulkan SDK. Imposta `WEBVIEW2_USER_DATA_FOLDER` su una cartella di prova, così la WebView non condivide i dati con l'app di sviluppo, e `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9223`.
3. `(Get-Process -Id <pid>).Modules`: `onnxruntime.dll`, `transcribe.dll`, `ggml*.dll`, `msvcp140*.dll` e `vcruntime140*.dll` devono venire da `<cartella>`, `vulkan-1.dll` da System32. Il log (`%LOCALAPPDATA%\it.sbobino.desktop\logs\Sbobino.log`, lo stesso dell'app di sviluppo) riporta `backend di transcribe-cpp: Vulkan0 (…), CPU (…)` e il caricamento del modello.
4. Via CDP sulla 9223 (vedi "Pilotare l'app"): `transcribe` su una copia di `parlato-it.wav` fuori dal repo, poi `record`, qualche secondo e `stop_recording`. Cancella il Bino della Trascrizione e la Registrazione di prova da `Documenti\Sbobino`.
5. Chiudi l'app e lancia `<cartella>\uninstall.exe /S`: la cartella e la chiave `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\Sbobino` spariscono, i modelli restano.

L'app installata usa la stessa `%APPDATA%\it.sbobino.desktop` dell'app di sviluppo, quindi anche i modelli già scaricati: `app_data_dir` viene da `FOLDERID_RoamingAppData` e una variabile d'ambiente non lo sposta. Durante la prova non cambiare le impostazioni. La finestra dell'app installata compare sullo schermo dell'utente, che può usarla: un `activityInProgress` inatteso viene da lì.

Esito del 2026-10-03 (Ryzen 7 3700X, RTX 2070 SUPER): tutte le DLL caricate dalla cartella d'installazione, backend Vulkan0 e CPU (modulo `ggml-cpu-haswell`), Nemotron caricato in 1,1 s, fixture trascritta in 1,3 s con il TXT salvato, Registrazione di 4 s salvata e ritrascritta, disinstallazione pulita. Manca la prova su un PC pulito (vedi "Da verificare sull'hardware reale").

## Insidie

### Toolchain e tooling

- **Tauri**: crate `tauri` e pacchetti `@tauri-apps/*` devono condividere major e minor (oggi 2.12), altrimenti la CLI si rifiuta di partire. I plugin seguono la stessa regola (`tauri-plugin-log` 2.10 con `@tauri-apps/plugin-log` 2.10). Tauri 3 è in alpha: le versioni npm sono pinnate esatte per non agganciare prerelease.
- **specta**: `specta`, `tauri-specta` (`=2.0.0-rc.25`) e `specta-typescript` (`=0.0.12`) restano pinnati con `=`; un aggiornamento può cambiare il formato di `bindings.ts`.
- **Tipi esportati**: niente `u64`/`i64`, bloccano l'export dei bindings. Usa `u32` (tutti i modelli stanno sotto i 4 GiB) o `f64`.
- **`bindings.ts`**: si rigenera solo in debug all'avvio dell'app (`bun tauri dev`). Il test `i_bindings_committati_sono_aggiornati` fallisce se il file committato non corrisponde ai comandi Rust: rigeneralo e committalo.
- **`cargo test` e il manifest Windows**: `tauri-plugin-dialog` richiede Common Controls v6. `build.rs` incorpora `windows-app-manifest.xml` in tutti gli eseguibili, test compresi; senza, i test escono con `STATUS_ENTRYPOINT_NOT_FOUND`.
- **TypeScript**: resta su 6.0.3, non la 7 (binari nativi, API JS sperimentale). In TS 6 `types` vale `[]` per default: i tipi globali (`bun`, `node`) vanno elencati nel tsconfig.
- **react-router**: resta su 7.18.x, non la 8.
- **Biome**: senza un `"**"` iniziale negli `includes` Biome non controlla nessun file (era il bug del template). Il core di ultracite 7.12 lo mette già, quindi in `biome.jsonc` restano solo le negazioni (`components/ui`, `bindings.ts`): ripetere `"**"` fa scattare `noBiomeFirstException`, e `ultracite fix` lo toglie. Se aggiorni ultracite, verifica che un `debugger` in `src/` venga ancora segnalato.
- **shadcn**: `components.json` è scritto a mano (stile `new-york`, base `neutral`); si usa solo `shadcn add`, perché `init` ora parte dai preset. I componenti importano `cn` dal pacchetto `cn`: è voluto (changelog shadcn del 2026-09-03), e `@/lib/utils` lo ri-esporta. Non riscrivere l'import.
- **Animazioni**: `tw-animate-css` è importato in `global.css`. `tailwindcss-animate` è il plugin di Tailwind 3 e non serve.
- **Line ending**: `.gitattributes` forza LF, come si aspetta Biome.
- **reqwest**: usa `native-tls` (Schannel) senza feature di default. Il default rustls + aws-lc richiede NASM sulla build MSVC.
- **zip**: 8.6 senza feature di default (AES, bzip2, zstd, lzma…), solo `deflate-flate2-zlib-rs`, in Rust puro. La 9 è in pre-release. `mix.ogg` deve restare `Stored`: `tape::Mix` lo legge come finestra sul file e rifiuta una voce compressa.
- **Download e Annulla**: il trasferimento corre in un `tokio::select!` contro il `Notify` di Annulla. Il `.partial` si cancella solo dopo l'uscita dal `select!`, quando il future e il suo file sono già chiusi: su Windows un file aperto non si cancella. Il `select!` serve perché un trasferimento fermo non restituisce chunk, quindi un flag controllato a ogni chunk non scatterebbe. Durante la verifica l'hash gira in un thread bloccante con il file aperto: Annulla si controlla a hash finito, prima del rename. Nel codice e nei documenti il file scaricato a metà è il "`.partial`" o il "file incompleto", non il "parziale": Parziale è un termine del glossario.

### Audio e motore

- **rubato 5** non ha `FftFixedIn`: si usa `Fft` con `FixedSync::Input` e buffer `audioadapter`.
- **Symphonia** non ha una feature `opus`: Opus passa da `symphonia-adapter-libopus`.
- **opus** 0.4 compila libopus 1.6.1 da sorgente con CMake (via `opusic-sys`, link statico): niente DLL da distribuire. L'encoder accetta solo 8/12/16/24/48 kHz, quindi la frequenza del dispositivo (spesso 44,1 kHz) si ricampiona sempre prima.
- **cpal 0.18**: `DeviceTrait::name()` non c'è più, il nome è `device.to_string()` e l'id stabile è `device.id()` (`Display`/`FromStr`, formato `wasapi:{…}`). Gli stream non partono senza `play()`. Gli stream di cattura WASAPI accettano solo il formato nativo (di solito f32 alla frequenza del mix): `capture` gestisce f32, i16 e i32.
- **chrono**: è già nel grafo tramite Tauri, con `clock`; serve per la data e ora locali nel nome delle Registrazioni.
- **ONNX Runtime**: niente build prebuilt di `ort` (compilata AVX2, va in crash all'avvio sulle CPU pre-Haswell) e niente `DirectML.dll`. Si usa l'ONNX Runtime ufficiale 1.24.2 in link dinamico (`ORT_LIB_LOCATION` + `ORT_PREFER_DYNAMIC_LINK=1`): `build.rs` copia `onnxruntime.dll` in `target/<profilo>`, in `target/<profilo>/deps` (per i test) e in `runtime-libs/` per il bundle. Senza quella copia Windows carica l'`onnxruntime.dll` di System32 (Windows ML), più vecchio, e l'avvio fallisce.
- **Silero**: il file è `silero_vad.onnx` dal tag v4.0 di snakers4/silero-vad (1 807 522 byte, SHA-256 `a35ebf52fd3ce5f1469b2a36158dba761bc47b973ea3382b3186ca15b1f5af28`). vad-rs accetta solo 8 o 16 kHz.
- **transcribe-cpp**: la feature di default è `metal`, quindi `default-features = false` con `vulkan`.
  - Con `vulkan` serve il Vulkan SDK: `build.rs` aggiunge `%VULKAN_SDK%\Lib` al percorso del linker per `vulkan-1.lib`. La prima build nativa dura diversi minuti.
  - `transcribe-cpp-sys` compila passando da una junction NTFS corta in `%LOCALAPPDATA%\tcs`, perché MSBuild ignora `LongPathsEnabled`. **Dentro l'app desktop di Claude `%LOCALAPPDATA%` è virtualizzato e CMake fallisce con "os error 267"**: per questo il `.cargo/config.toml` locale sposta `LOCALAPPDATA` in `src-tauri/target`. Se la junction fallisce comunque, usa un `CARGO_TARGET_DIR` corto (es. `C:\tc-target`).
  - Una build Rust alla volta: due build contemporanee condividono la cartella CMake. Se si corrompe, cancella `src-tauri/target/debug/build/transcribe-cpp-sys-*`.
  - **`dynamic-backends`, in dev come in release.** La build statica sarebbe ottimizzata per la CPU della macchina di build. Con `dynamic-backends` ci sono `transcribe.dll`, `ggml.dll`, `ggml-base.dll`, un `ggml-cpu-<livello>.dll` per livello di ISA (da `x64`/`sse42` a `alderlake`/`icelake`, scelto a runtime) e `ggml-vulkan.dll`. `TranscribeCpp::load` chiama `init_backends_default` una volta per processo, che cerca i moduli accanto a `transcribe.dll`; il log dice quali dispositivi si sono registrati. In dev funziona uguale (smoke test con Vulkan), quindi c'è una sola configurazione e quello che si prova in dev è quello che si installa. Cambiare le feature ricompila CMake da capo (circa 4 minuti e mezzo).
  - transcribe-cpp-sys copia le sue DLL in `target/<profilo>` e `deps`; `build.rs` le prende da `DEP_TRANSCRIBE_CPP_RUNTIME_DIR`/`MODULE_DIR` e le mette in `runtime-libs/`, togliendo quelle che non servono più. Debug e release scrivono nella stessa cartella, ma va bene: la sys compila CMake in `Release` in entrambi i profili. `build.rs` copia solo i file cambiati: tauri-build mette `rerun-if-changed` sulle risorse, e riscrivere le DLL a ogni build farebbe ripartire build script e compilazione ogni volta (`fs::copy` su Windows conserva la data).
  - `ggml-vulkan.dll` dipende da `vulkan-1.dll`, il loader che installano i driver della GPU: non si distribuisce. Se manca, il modulo non si carica e transcribe-cpp usa la CPU.
  - **`vcomp140.dll` non serve**: OpenMP è spento in 0.2.4 e `dumpbin /dependents` non lo trova in nessuna DLL. Servono invece `msvcp140.dll`, `msvcp140_1.dll`, `vcruntime140.dll` e `vcruntime140_1.dll` (ggml, transcribe e ONNX Runtime sono C++ con `/MD`): vanno nel bundle dal redistribuibile di VS, perché un PC pulito può non averli. Devono essere almeno della versione del toolset che ha linkato le DLL (14.44 per ONNX Runtime 1.24.2 e per transcribe.cpp qui): `build.rs` rifiuta un redistribuibile più vecchio. L'exe di Sbobino invece linka statico il vcruntime (lo fa tauri-build) e usa solo l'UCRT di Windows.
- **Loopback WASAPI**: è uno stream di input aperto sul dispositivo di uscita, con la config da `default_output_config()` (il mix format, di solito f32 48 kHz stereo); `default_input_config()` lì dà errore. Verificato su Windows 11 (26200) con un'uscita USB Focusrite:
  - a riproduzione ferma il loopback non consegna nessun pacchetto, nemmeno di silenzio: timer e file avanzano solo grazie a `advance` con l'orologio QPC;
  - all'inizio e alla fine di ogni riproduzione arriva spesso un `Xrun` (discontinuità), che si ignora: il buco diventa silenzio;
  - mic e loopback hanno lo stesso orologio (QPC) e si allineano per timestamp, non per numero di campioni.
- **Deriva misurata** (Windows 11, sessione Entrambi di 4 min con il microfono USB Anker PowerConf C200 e l'uscita Focusrite): il microfono ha consegnato 235 700 ms di audio in 235 697 ms di QPC (+3 ms, circa 13 ppm); il loopback, dopo una discontinuità da 20 ms all'avvio della riproduzione, nessuna correzione per 234 s, quindi meno di 20 ms. Mic e uscita non si sono scostati di più di 20 ms tra loro. All'avvio il mixer scarta i blocchi del microfono catturati prima dell'origine (100–170 ms, il tempo di aprire il loopback).
- **Istanza unica e dev**: il mutex di `tauri-plugin-single-instance` ha il nome dell'identifier, quindi l'app installata e `bun tauri dev` sono la stessa istanza: con una aperta, l'altra non parte e passa gli argomenti alla prima. Per provare il secondo avvio in dev lancia `target\debug\sbobino.exe "<file>.bino"` con cwd `src-tauri`. L'export di `bindings.ts` sta nel `setup` per questo: prima del plugin, il secondo avvio riscriveva il file e Vite ricaricava la pagina dell'istanza aperta.
- **Cartelle dell'app**: l'identifier Tauri è `it.sbobino.desktop`, non `sbobino`: `%APPDATA%\sbobino` appartiene a una vecchia app con lo stesso nome e va lasciata intatta. Quindi `app_data_dir` è `%APPDATA%\it.sbobino.desktop` (roaming), mentre `app_local_data_dir` è `%LOCALAPPDATA%\it.sbobino.desktop` ed è anche la cartella dati della webview. Tauri sconsiglia un identifier che finisce in `.app`.
- **Progresso**: la percentuale viene da frame decodificati / `Track::num_frames`. Il demuxer MKV di Symphonia 0.6 non imposta `num_frames`, quindi per i MKV l'avanzamento è sempre indeterminato; idem per i WAV "in streaming" (lunghezze `0xFFFFFFFF`), che finiscono con un `UnexpectedEof` trattato come fine del file.

- **Lingue del modello**: transcribe-cpp 0.2.4 non legge i metadati senza caricare il modello, quindi `capabilities().languages` si conosce solo dopo un `Model::load`. Per questo il modello scelto si carica all'avvio. Nemotron dà 32 locale (`it-IT`, `en-US` ed `en-GB`…), Whisper 99 codici (anche `yue`, `haw`), Parakeet 25 codici europei.
- **Prima Diarizzazione**: anche Sortformer paga il riscaldamento di Vulkan una volta per processo: 9,3 s sui 25 s della fixture la prima volta, poi 0,5 s; 513 s di audio in 3 s (RTX 2070 SUPER). Sortformer vuole tutto il PCM in un buffer (230 MB/ora di audio a 16 kHz in f32) e ne dà i segmenti ordinati per parlante, non per tempo.
- **Prima chiamata a un modello**: dopo il caricamento la prima chiamata dura parecchio di più. Con Whisper erano 16 s contro 0,8 s sulla fixture (RTX 2070 SUPER con Vulkan), anche senza ricaricare il modello: è il riscaldamento di Vulkan, non un ricaricamento. Per questo `TranscribeCpp::load` riscalda il modello, e il tempo finisce nel caricamento in background (`<id> caricato in …` di `managers::models` lo comprende).

### Frontend e verifica manuale

- **Numeri in italiano**: con `{{count, number}}` Intl non raggruppa le migliaia sotto 10 000 (`minimumGroupingDigits` 2 nel CLDR italiano): 1234 resta "1234", 12345 diventa "12.345".
- **Watcher di `tauri dev`**: qualunque file cambi sotto `src-tauri/`, anche un Markdown creato in `tests/fixtures` da una Trascrizione di prova, ricompila e riavvia l'app. I download in corso si interrompono e il `.partial` resta. Per le prove trascrivi copie delle fixture fuori da `src-tauri`.
- **Provare il server MCP**: senza client, con le righe JSON-RPC su stdin di `target\debug\sbobino.exe --mcp` (cwd `src-tauri`): `initialize`, `notifications/initialized`, `tools/list`, `tools/call`. Legge le impostazioni e l'indice veri, quindi con l'interruttore spento ogni strumento risponde `DISABLED`; non accenderlo nelle impostazioni dell'utente per provare. I test di `mcp` usano una Libreria e un `settings.json` temporanei (`Places`). L'exe di release è senza console: stdin e stdout funzionano solo se chi lo lancia passa le pipe, come fanno i client MCP; lanciato a mano non mostra nulla.
- **Pilotare l'app**: con `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222` la WebView2 di `bun tauri dev` si comanda via CDP. Il dialog di Sfoglia è nativo e UI Automation da PowerShell 5.1 vede i suoi controlli solo come `Pane`: si compila con Win32, `WM_SETTEXT` sull'`Edit` dentro il controllo 1148 e `BM_CLICK` sul pulsante 1 del dialog `#32770` "Apri". `SendKeys` non arriva, perché la finestra di Claude tiene il foreground. Per chiamare un comando senza passare dalla UI (per esempio un secondo `transcribe` durante un'Attività) c'è `window.__TAURI_INTERNALS__.invoke("transcribe", { source, raccolta: null })`.
- **Vedere i Parziali**: con la GPU Nemotron trascrive molto più veloce del tempo reale e un Parziale resta a schermo per circa 250 ms. Per verificarli registra il valore dell'area a ogni `requestAnimationFrame` via CDP e usa un parlato lungo (frasi da 10–15 s), per esempio generato con `System.Speech` (voce "Microsoft Elsa Desktop") in una cartella fuori dal repo.
- **Chiudi tutto dopo la verifica**: fermare `bun tauri dev` può lasciare vivo il server Vite sulla porta 1420. Chiudi l'app e il Vite, e prima di lanciare una build controlla che non ci sia già un `tauri dev` attivo (anche dell'utente): il suo watcher ricompila a ogni modifica sotto `src-tauri/`.
- **`%APPDATA%` nell'app desktop di Claude**: anche il roaming è virtualizzato (MSIX). Le scritture di un processo lanciato da Claude finiscono in un livello privato, le letture vedono quel livello sopra il file reale. Spostare o cancellare `settings.json` da una shell di Claude può far ricomparire il file reale, più vecchio: per simulare un file illeggibile tienilo aperto in esclusiva (`[IO.File]::Open(p, 'Open', 'ReadWrite', 'None')` in PowerShell) mentre l'app parte, e non toccare il file reale.
- **Ascoltare il player via CDP**: l'audio di `bino.localhost` è cross-origin per la pagina, quindi `createMediaElementSource` e `captureStream` lo ricevono muto. Per misurare (vedi `docs/research/libreria-e-player.md`) serve `Access-Control-Allow-Origin` nella risposta di `player::respond` e `crossOrigin = "anonymous"` sul tag prima di `load()`, solo durante la prova. Un `AnalyserNode` tiene gli ultimi campioni anche in pausa: dopo uno spostamento aspetta un buffer silenzioso prima di cercare l'inizio di un suono.
- **Stub dei comandi via CDP**: `window.__TAURI_INTERNALS__` e il suo `invoke` non sono né scrivibili né configurabili, quindi non si può far fallire un comando dalla pagina. Il tema invece si prova con `Emulation.setEmulatedMedia` (`prefers-color-scheme`), nella stessa sessione CDP dello screenshot.
- **Popover e Tailwind**: lo UA nasconde un popover chiuso con `[popover]:not(:popover-open) { display: none }`, che una classe come `flex` scavalca: il pannello resterebbe visibile. Si usa `hidden open:flex` (in Tailwind 4 `open:` vale anche per `:popover-open`).
- **Dialog di salvataggio e `tauri dev`**: "Salva con nome" si apre nell'ultima cartella usata e ci prova a scrivere. Se è sotto `src-tauri/` (per esempio `tests/fixtures` dopo una prova di Apri file) il watcher ricompila e riavvia l'app, chiudendo il dialog. Per provare Esporta Markdown… lancia Vite (`bun run dev`) e `target\debug\sbobino.exe` (cwd `src-tauri`) senza `tauri dev`. Nel dialog di Apri il nome del file è l'`Edit` dentro il controllo 1148, in "Salva con nome" è l'`Edit` con id 1001.
- **Niente drag and drop HTML5**: con `dragDropEnabled: true` wry sostituisce il drop target della WebView2 e non inoltra a Chromium i trascinamenti senza file. `draggable` e gli eventi `drag*` non danno errori: semplicemente non scattano. Un trascinamento interno va fatto con i pointer event (ADR-0011).
- **Il drop dei file non si simula via CDP**: arriva da Windows, non dalla pagina. Si prova trascinando da Esplora file.
- **Selettori nativi via CDP**: per un `<select>` o un `<textarea>` controllato da React non basta assegnare `value`. Si usa il setter del prototipo (`Object.getOwnPropertyDescriptor(HTMLSelectElement.prototype, "value").set.call(el, v)`) e poi si emette un evento `change` (o `input`) con `bubbles: true`.

### Da verificare sull'hardware reale

Un dispositivo che consegna con oltre 500 ms di ritardo verrebbe scartato per intero (`LAG_NS`).

- L'installer su un PC Windows x64 pulito (una VM va bene), da fare a mano: senza Visual Studio né redistribuibile VC++, senza Vulkan (solo CPU) e se possibile con una CPU pre-AVX2 (moduli `ggml-cpu-sse42`/`x64`, ONNX Runtime ufficiale).
